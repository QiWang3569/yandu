# AI 模块监控与评测口径

**线上监控**回答“运行是否稳定”，**离线评测**回答“结果是否正确”。调用成功、模型没有报错，不代表输出符合用户需求。

## 线上：按业务节点看健康度

| 节点 | 统计范围 |
| --- | --- |
| `intent_parse` | 远程需求解析，求购文本解析复用此节点 |
| `item_parse` | 文本生成商品草稿 |
| `candidate_review` | 一批非空候选的精筛 |
| `embedding` | 向量请求及向量维度、数值校验 |
| `vision_draft` / `vision_batch` | 实际发出的单件或批量识图操作，缓存命中及共享等待不重复记数 |

- `yandu_model_calls_total{node,status}`：一个远程业务操作计一次；`ok` 表示通过业务输出校验。网络、HTTP、JSON 及无效输出归为 `error`。
- `yandu_model_latency_seconds{node}`：以上操作的端到端耗时，含同一次操作内的重试。用 `histogram_quantile` 看分节点 P95；先看请求量，低流量分位数不稳定。
- `yandu_model_fallbacks_total{node}`：远程失败后，实际切到本地规则的次数；直接使用本地模式不计。
- `yandu_model_tokens_total{node,kind}`：最后返回的服务商用量（若提供输入／输出字段）。不估算缺失值，不代表完整账单，也不累计多次尝试的用量。

Prometheus 从容器内 `app:8000/metrics` 拉取。仓库中的 Caddy 配置不向公网转发 `/metrics`；独立维护的生产反代也应有等效规则。这些 AI 指标不记录提示词、用户输入、用户标识或供应商错误正文。

后台「平均成交周期」使用商品发布到第一次有效买家确认的间隔，每个商品算一次。没有确认记录时显示「暂无成交样本」，不把最后一条消息、卖家标记售出或固定天数当成实际确认。

## 离线：按模块看错误

| 模块 | 优先看的指标 | 解读要点 |
| --- | --- | --- |
| 文本商品草稿 `item_parse` | 整例通过率、类目/价格/校区等字段命中、标签 P/R/F1 | 不拿字段平均值代替“整条全对”。 |
| 需求／求购解析 `intent_parse` / `wanted_parse` | 整例通过率、商品词／排除词／偏好集合 P/R/F1、价格和校区 | 漏掉排除词比漏掉普通偏好更严重；同时看原始输出和回退后输出。 |
| 图片草稿 `vision_draft` | 状态／类目准确率、禁提词命中率、无法评分数 | 准确率仅以已标注该字段的样本作分母，已标注但运行失败算错误。禁提词命中率只覆盖预标注的词，不是通用幻觉率；模型失败单列。 |
| 搜索 `smart_search` | Recall@10、MRR、MAP@5、零结果误杀、收紧约束后的变化 | 固定库与人工相关性标签；检索正例与应返回空的样本分开。离线回归不证明线上向量服务表现。 |
| 候选精筛 `candidate_review` | MATCH 召回率及正例数、误推荐率、macro-F1、证据规则通过率 | 证据规则只检查原文引用和条件覆盖等结构约束，不证明引用的意思支持结论。无 MATCH 正例时不填召回率；无关商品误判 MATCH 和漏掉真 MATCH 分开看。 |

1124 分支的概念族评测暂不接入：需另验标注并冻结一份未用于调提示词的保留集。复用 [现有评测流程](MODEL_EVALUATION.md)，不另起 runner、不改变当前选型门槛。开发用例、oracle 和本地规则只用于回归，不能作为实际远程模型质量或生产准入证据。
