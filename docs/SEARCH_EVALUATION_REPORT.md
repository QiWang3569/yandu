# 搜索评测扩展与首轮离线结果

后续已完成六款远程候选、七个配置的三轮横测，见[最新模型选型报告](MODEL_SELECTION_REPORT.md)。本文保留扩展完成时的首轮离线诊断。

2026-11-15，按《评测方法(1).pdf》完成固定商品库、七类场景、蜕变关系和稳定性统计。使用 52 件合成商品、80 条预标注开发查询，local 与 oracle 各重复 3 次，共 480 条执行记录。运行 ID 为 `20261115T105148Z-80c171dd`，评分器 `1.2.0`。

## 本轮结果

| 对照 | 整例通过（唯一查询） | MRR | MAP@5 | Recall@10 | 蜕变关系通过（唯一关系） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 本地规则 | 21/80（26.25%） | 0.7549 | 0.7487 | 0.8571 | 9/12 |
| Oracle：注入预标注解析 | 60/80（75.00%） | 0.9429 | 0.9412 | 0.9686 | 11/12 |

重复执行后的整例通过数分别为 63/240 和 180/240。排名指标的每组分母为 70 个有相关商品的查询 × 3 次；4 个应无结果查询和 6 个仅评价歧义／冲突解析的查询不计入排名均值。零结果误杀率分别为 27/210（12.86%）和 6/210（2.86%）。

本地规则有 1 个查询在三次执行中均发生结构校验错误，因此“全部重复成功且输出一致”的比例为 79/80；其余本地查询输出一致。Oracle 的 80 个查询全部重复一致。这不是本地规则随机波动，而是失败记录没有被计作稳定成功。

所有数据由 Codex 构造与预标注，仍为 draft/dev。这里的 Oracle 只注入解析答案，仍调用实际商品过滤和排序；不是人工审定上限。六款远程候选尚未在本轮横测，因此不据此推荐模型。

## 新机制发现的问题

| 例子 | 实际观察 | 涉及环节 |
| --- | --- | --- |
| 万柳 150 以内无线鼠标 | Oracle 已正确解析“鼠标、无线”，结果仍混入无线路由器 | 当前召回允许任一关键词命中，多项必须条件没有全部落实 |
| 400 以内静音鼠标 | Oracle 返回了未标明静音的鼠标，导致新增硬条件的关系检查失败 | 必须特征与普通相关性排序的区别未落实为过滤 |
| 键盘、MacBook 电脑 | 返回键盘接收器，或充电器、支架等配件 | 关键词匹配没有充分区分商品主体与配件 |
| 100 以内鞋子，最好白色 | Oracle 的“鞋子”未匹配到描述中的“跑步鞋／运动鞋” | 检索词形归一化存在缺口 |
| 两百多买鼠标 | 预标注按约数需求处理，线上约数检测未触发 | 需要团队确认“多”的业务容差约定并补充规则 |
| 静音鼠标，不要静音 | 本地解析冲突导致校验失败，回退后再次失败 | 评测保留错误并继续后续样本，没有把回退当成模型正确 |

这些失败没有通过修改答案来消除。它们说明：即使解析正确，检索仍可能召回不相关商品或漏掉真正相关商品。后续模型比较应同时查看解析指标和实际搜索结果；仅更换解析模型不能保证上述检索问题消失。

## 已完成的工程内容

- `smart_search` 复用实际解析、过滤、排序流程；商品库在独立内存数据库中运行，快照及哈希随报告保存。
- 七类场景各 10 条基础查询，加 10 条改写／预算变换；按 `slice:` 标签输出分组结果。
- 增加单值字段准确率和 Macro-F1、集合 Micro/Macro-F1、澄清触发 F1、首次 Schema 通过率、重复一致率和相对本地整例错误率降低。
- 12 组蜕变关系比较完整结果集；预先声明的同义词用于解析不变性判定，避免措辞差异误报。
- 搜索评分包含 MRR、MAP@5、Recall@10 和零结果误杀率，并保留各项分母。解析、检索与服务流程总耗时分别记录。
- 回归比较覆盖整例通过、评分、排名和关系退化；商品库或关系定义改变时拒绝混用旧基线。
- 六个七牛候选已配置，另有 DeepSeek 思考模式开／关对照；修正豆包 ID。未核实的 PDF 单价没有写入计费配置。
- CI 增加固定库校验、local/oracle 三次重复运行和回归检查；旧版及图片首轮结果保留。

## 验证与下一轮

后端与评测合计 **417 项测试通过**；末次指标调整后，评测层 **120 项再次通过**。52 件商品、80 条用例、12 组关系通过校验，源生成器可以重建相同 JSON。原 40 例本地规则评分保持不变；搜索 480 条执行重跑后，整例、评分、排名和关系均无退化。
