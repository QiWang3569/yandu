## 详细修改

### 1. 成交后双向评价（#61 / #23）

两件 issue 是同一需求。此前只有「反馈已售」和「举报问题」，缺少交易完成后的信誉沉淀。

后端：

- 新表 `trade_reviews`：会话、商品、评价人、被评价人、1–5 星、文字（≤500 字）、标签、时间；`(conversation_id, reviewer_id)` 唯一。
- `POST /api/v1/conversations/{id}/reviews`：仅会话双方、仅 `CONFIRMED` 状态、每人一次；行锁避免多进程重复写入。
- `GET /api/v1/conversations/{id}/reviews`：双方查看本次评价与是否还能评价。
- `GET /api/v1/users/{id}/reviews`：公开的平均分、评价数、5→1 星分布和最近评价，供买家在联系卖家前判断。
- 评价不会改变商品状态，也不会让已撤回/隐藏商品重新公开；非公开商品的标题显示为「已结束的交易」。

前端：

- 聊天窗口交易完成后显示一行评价状态；「评价对方 / 查看评价」打开弹窗，避免挤占聊天记录。
- 商品详情卖家卡片显示 `★ 平均分 · N 条评价`，点击查看完整评价。
- 个人主页显示自己收到的评分，并可在弹窗中查看评价列表。

限制与说明：

- 评价提交后不可编辑或删除；管理员暂未提供删除评价的工具。
- 双方可以互相评价，存在「互刷好评」的可能；后续可加入仅成交双方可见的订单校验、举报评价或时间窗。
- 新评价暂时只写入 `action_logs`，没有额外站内信提醒；需要的话可复用通知中心。

### 2. 相似商品推荐（#25）

- 新接口 `GET /api/v1/items/{id}/similar?limit=6`（1–12）。
- 仅返回 `ACTIVE` 商品，排除自身，生产环境排除演示账号；在最近 400 件商品内按「同分类 + 共同标签 + 同校区 + 同成色 + 价格接近度」打分排序。
- 商品详情弹窗底部新增「相似好物」，展示缩略图、标题、价格与校区，点击直接切换详情。
- 纯 Python 打分不依赖模型/embedding，离线与本地演示模式可用。

### 3. 会话删除（#54）

该 issue 只有标题和 `bug` 标签，无法确定具体指哪一处删除。代码核查结果：

- 商品已有「撤回」；草稿可删除；求购可关闭；代蹲可结束；公告原本只能下线。
- 聊天会话没有任何移除入口，是最明显的删除缺口，因此本次按「删除会话」实现。

行为：

- `DELETE /api/v1/conversations/{id}` 只把当前用户一侧标记为已移除，不删除聊天记录；对方仍可查看。
- 移除后该会话从「站内消息」列表消失，未读角标清零；对方发来新消息会自动恢复显示。
- 预订/待确认等交易进行中的会话禁止移除（409），避免双方丢失交易上下文；成交确认后可以移除。
- 深链接 `#messages/{id}` 与邮件链接仍可打开会话，权限仍由后端校验。

没有做的部分：商品、求购仍保持「撤回 / 关闭」而不是物理删除，这是现有交易与聊天记录可追溯性的设计选择。如果 #54 指的是其他位置（例如彻底删除已撤回商品、删除单条消息、删除通知），需要补充具体操作路径。

### 4. 管理员面板（#50）

- 新接口 `GET /api/v1/admin/summary` 返回商品举报、聊天举报、用户反馈、在线公告的计数。
- 侧边栏「审核工作台」和审核页签显示待办角标，管理员不在审核页时也能看到待处理数量。
- 公告管理新增「删除」：先清理 `announcement_reads` 再删除公告，避免外键悬挂。
- 商品举报默认只显示待处理记录，可切换「显示已处理」回看历史。
- 未改动审核表单的复杂流程；issue 若指具体页面布局，仍需要更具体的描述。

### 5. 聊天窗口尺寸（#66）

- 原逻辑把高度硬限制在 `min(650px, 可用高度)`，大屏上会留下大片空白。
- 现在按 `可视高度 - 顶部位置 - 手机底部导航 - 16px` 计算，范围 360–1080px；CSS 兜底从 `65vh / 650px` 提高到 `78vh / 900px`。
- 手机端兜底从 `calc(100dvh - 320px)` 调整为 `calc(100dvh - 220px)`，最小高度 380px。
- 浏览器实测：1440×900 下高度 622px（与旧的 622 相同，因为旧的 650 上限未触发）；更高屏幕上会随视口继续增长。手机 390×844 下高度 500px，未被底部导航遮挡。
